The health check block runs a list of checks, waits for all of them, and turns the results into one JSON report. A failed critical check makes the report `unhealthy`. A failed non-critical check makes it `degraded`.

The block has no root `index.ts`. Import `createHealth` from `core/create-health` and the framework helpers from `adapters/`.

## Quick start

```bash
pnpm dlx blockend-cli init
pnpm dlx blockend-cli add health-check
```

```ts
import express from "express";
import { createHealth } from "@/blocks/health-check/core/create-health";
import { registerExpressHealthRoute } from "@/blocks/health-check/adapters/express";

const app = express();

const health = createHealth({
  checks: [
    {
      name: "database",
      critical: true,
      timeoutMs: 5_000,
      async run() {
        await db.query("SELECT 1");
      }
    }
  ]
});

registerExpressHealthRoute(app, health); // GET /health
```

`registerExpressHealthRoute` returns 200 for `healthy` and `degraded`, and 503 for `unhealthy`. It does not add liveness or readiness endpoints. The production guide shows how to build those on top of `health.run()`.

## Configuration

`createHealth` takes one object:

| Option             | Type               | Default  | Description                                                        |
| ------------------ | ------------------ | -------- | ------------------------------------------------------------------ |
| `checks`           | `HealthCheck[]`    | Required | Checks to run. Must not be empty.                                  |
| `defaultTimeoutMs` | `number`           | `5000`   | Timeout for checks without `timeoutMs`.                            |
| `calculateStatus`  | `StatusCalculator` | Built-in | Maps results to `healthy`, `degraded`, or `unhealthy`.             |
| `buildReport`      | `ReportBuilder`    | Built-in | Builds the report returned by `run()`. Must return `HealthReport`. |

Each `HealthCheck` has these fields:

| Field       | Type                  | Required | Description                                              |
| ----------- | --------------------- | -------- | -------------------------------------------------------- |
| `name`      | `string`              | Yes      | Unique name used in the report.                          |
| `critical`  | `boolean`             | Yes      | When true, a failure makes the whole report `unhealthy`. |
| `run`       | `() => Promise<void>` | Yes      | Throw to fail the check. Return normally to pass.        |
| `timeoutMs` | `number`              | No       | Per-check timeout. Overrides `defaultTimeoutMs`.         |
| `message`   | `string`              | No       | Text included in the result.                             |

## Usage

### Express

```ts
import express from "express";
import { createHealth } from "@/blocks/health-check/core/create-health";
import { registerExpressHealthRoute } from "@/blocks/health-check/adapters/express";

const app = express();

const health = createHealth({
  checks: [
    {
      name: "postgres",
      critical: true,
      async run() {
        await db.query("SELECT 1");
      }
    },
    {
      name: "redis",
      critical: false,
      timeoutMs: 2_000,
      async run() {
        await redis.ping();
      }
    }
  ]
});

registerExpressHealthRoute(app, health);
```

### Fastify

```ts
import Fastify from "fastify";
```

### Custom status logic

```ts
const health = createHealth({
  checks,
  calculateStatus(results) {
    if (results.every((result) => result.status === "healthy")) return "healthy";
    if (results.some((result) => result.critical && result.status === "unhealthy")) {
      return "unhealthy";
    }
    return "degraded";
  }
});
```

### Custom report fields

`buildReport` must return a `HealthReport`. If you need extra fields for your own endpoint, add them after `run()`:

```ts
app.get("/health", async (_req, res) => {
  const report = await health.run();

  res.status(report.status === "unhealthy" ? 503 : 200).json({
    ...report,
    version: process.env.APP_VERSION ?? "dev"
  });
});
```

Do not return extra fields from a custom `buildReport` without widening the type. They are not part of the `HealthReport` contract and will fail type checking.

## API reference

### `createHealth`

```ts
function createHealth(options: CreateHealthOptions): Health;
```

Validates the config immediately. It throws when `checks` is missing or empty, a check name is empty or duplicated, a check has no `run` function, or a timeout is not a positive number.

### `health.run`

```ts
async function run(): Promise<HealthReport>;
```

Runs every check concurrently and waits for all of them. One check cannot hang the request because each check is bounded by its timeout.

### `HealthReport`

```ts
interface HealthReport {
  status: "healthy" | "degraded" | "unhealthy";
  timestamp: string;
  uptime: number; // seconds
  checks: HealthCheckResult[];
}

interface HealthCheckResult {
  name: string;
  critical: boolean;
  status: "healthy" | "unhealthy";
  duration: number; // milliseconds
  message?: string;
  error?: string;
}
```

`error` is a string, not an `Error` object, so stack traces do not reach the response.

## Behavior

- All checks run at the same time with `Promise.all`.
- Each check gets its own timeout. The default is 5 seconds.
- A critical failure sets the report to `unhealthy`.
- A non-critical failure sets it to `degraded`.
- If every check passes, the report is `healthy`.
- The adapter maps only `unhealthy` to 503. `degraded` stays on 200 so the instance keeps serving traffic.

## When not to use it

- You only need a fixed `{ ok: true }` liveness endpoint. A route is enough.
- You need metrics or tracing. This block returns a snapshot, not a time series.
- You need to run checks in the background. This block runs them when `health.run()` is called.
