The environment configuration block parses `process.env` with a Zod schema and throws `EnvValidationError` when a value is missing or invalid. It runs once at startup, so the rest of your app gets a typed object instead of raw strings.

The block exports from its root `index.ts`. It does not load `.env` files.

## Quick start

```bash
pnpm dlx blockend-cli init
pnpm dlx blockend-cli add env-config
```

```ts
import { z } from "zod";
import { parseEnv } from "@/blocks/env-config";

export const env = parseEnv(
  z.object({
    NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
    PORT: z.coerce.number().int().positive().default(3000),
    DATABASE_URL: z.string().url(),
    JWT_SECRET: z.string().min(32)
  })
);

console.log(env.PORT); // number
```

If `DATABASE_URL` is missing or is not a URL, startup fails with an error that lists every invalid field.

## Loading `.env` files

The block reads `process.env` by default. It does not import `dotenv` and does not read a file.

Use the runtime's environment loader:

```bash
node --env-file=.env dist/server.js
```

Node 20.6 and later support `--env-file`. In production, set variables through your platform's secret manager or container environment.

If you already use `dotenv`, load it before importing the module that calls `parseEnv`:

```ts
import "dotenv/config";
import { env } from "./config/env";
```

Order matters. `parseEnv` reads the environment when your config module runs. Loading `.env` after that is too late.

## Usage

### Define a schema

```ts
import { z } from "zod";
import { parseEnv } from "@/blocks/env-config";

const schema = z.object({
  NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
  PORT: z.coerce.number().int().positive().default(3000),
  DATABASE_URL: z.string().url(),
  REDIS_URL: z.string().url().optional(),
  JWT_SECRET: z.string().min(32)
});

export const env = parseEnv(schema);
```

Zod coercion turns strings into numbers and booleans:

```ts
z.coerce.boolean(); // "false" becomes true
z.coerce.number(); // "3000" becomes 3000
```

`z.coerce.boolean()` treats any non-empty string as true, including `"false"`. Use an enum for boolean flags:

```ts
FEATURE_X: z.enum(["true", "false"])
  .default("false")
  .transform((value) => value === "true");
```

### Test with a custom source

`parseEnv` accepts a second argument, so tests do not need to mutate `process.env`:

```ts
import { parseEnv } from "@/blocks/env-config";

const env = parseEnv(schema, {
  NODE_ENV: "test",
  PORT: "4000",
  DATABASE_URL: "postgres://localhost/test",
  JWT_SECRET: "test-secret-with-at-least-32-characters"
});
```

### Catch validation errors

```ts
import { EnvValidationError, parseEnv } from "@/blocks/env-config";

try {
  const env = parseEnv(schema);
} catch (error) {
  if (error instanceof EnvValidationError) {
    console.error(error.issues);
    process.exit(1);
  }

  throw error;
}
```

`issues` is the raw Zod issue array. The error message is formatted for terminal output.

## API reference

### `parseEnv`

```ts
function parseEnv<T>(
  schema: z.ZodType<T>,
  source?: NodeJS.ProcessEnv | Record<string, string | undefined>
): T;
```

`schema.safeParse` runs against `source`. The default is `process.env`. On success you get the parsed object. On failure you get `EnvValidationError`.

### `EnvValidationError`

```ts
class EnvValidationError extends Error {
  readonly issues: readonly z.core.$ZodIssue[];
}
```

The instance is frozen. The message lists each failing path and its validation message.

## Behavior

- Validation runs when you call `parseEnv`, not at import time.
- All fields are validated in one pass. You get every issue, not just the first one.
- Defaults and transforms from the Zod schema are applied.
- Unknown keys in the environment are ignored because the default Zod object strips them.
- The returned object is a plain object. It is not re-read when the environment changes.

## Production notes

- Call `parseEnv` once in a config module and import that module everywhere else.
- Do not pass secrets to client bundles or log the parsed object.
- `z.string().url()` accepts any scheme the URL parser accepts. If your database driver also accepts non-URL connection strings, add a custom refinement.
- Keep `.env` out of version control. The block does not manage secrets.
- Validate `NODE_ENV` explicitly if behavior changes between environments.

## When not to use it

- Your platform validates configuration before the process starts.
- You prefer a different validation library.
- You need configuration that changes at runtime. This block reads once at startup.
