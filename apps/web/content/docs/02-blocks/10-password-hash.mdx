The password hash block hashes passwords with Argon2id. It adds a server-side pepper with HMAC-SHA256, generates a random salt for every hash, and returns a standard PHC string.

The block has no root `index.ts`. Import the class from `core`, errors from `errors`, and types from `types`.

<Callout type="warn">
  This block stores password hashes. It does not create users, authenticate requests, manage
  sessions, or rate limit login attempts. Those are application concerns.
</Callout>

## Quick start

```bash
pnpm dlx blockend-cli init
pnpm dlx blockend-cli add password-hash
```

Generate a pepper and store it as an environment variable:

```bash
openssl rand -base64 32
```

```bash
export APP_PASSWORD_PEPPER="<the generated value>"
```

```ts
import { PasswordHasher } from "@/blocks/password-hash/core";

const hasher = new PasswordHasher();

const hash = await hasher.hashPassword("correct horse battery staple");
const valid = await hasher.verifyPassword("correct horse battery staple", hash);

console.log(valid); // true
```

## Pepper setup

The pepper is a secret mixed into every password before Argon2 runs. It is not stored with the hash. An attacker who steals the database still cannot test password guesses without the pepper.

`APP_PASSWORD_PEPPER` must be valid base64 and decode to at least 32 bytes. The `openssl` command above produces a suitable value. Keep it in a secret manager, not in source control or a public environment file.

If the pepper is missing, invalid, or shorter than 32 bytes, `new PasswordHasher()` throws `InvalidPepperError`.

## Usage

### Hash a password

```ts
import { PasswordHasher } from "@/blocks/password-hash/core";

const hasher = new PasswordHasher();

app.post("/users", async (req, res) => {
  const hash = await hasher.hashPassword(req.body.password);

  const user = await db.user.create({
    data: {
      email: req.body.email,
      passwordHash: hash
    }
  });

  res.status(201).json({ id: user.id });
});
```

The stored string looks like this:

```text
$argon2id$v=19$m=65536,t=3,p=1$<salt>$<hash>
```

Store it in a text column long enough for future parameter changes. Do not split or parse it in application code.

### Verify a password

```ts
app.post("/login", async (req, res) => {
  const user = await db.user.findUnique({
    where: { email: req.body.email }
  });

  if (!user) {
    return res.status(401).json({ error: "Invalid credentials" });
  }

  const valid = await hasher.verifyPassword(req.body.password, user.passwordHash);

  if (!valid) {
    return res.status(401).json({ error: "Invalid credentials" });
  }

  if (hasher.needsRehash(user.passwordHash)) {
    const newHash = await hasher.hashPassword(req.body.password);
    await db.user.update({
      where: { id: user.id },
      data: { passwordHash: newHash }
    });
  }

  // Create a session or return a token.
  res.json({ ok: true });
});
```

Return the same error for an unknown email and a wrong password. Do not reveal which one failed.

### Configuration overrides

The constructor accepts overrides for tests and for apps that do not use environment variables:

```ts
const hasher = new PasswordHasher({
  pepper: process.env.APP_PASSWORD_PEPPER!,
  memoryCost: 65_536,
  timeCost: 3,
  parallelism: 1,
  outputLen: 32,
  maxInputBytes: 128
});
```

| Setting         | Environment variable       | Default     |
| --------------- | -------------------------- | ----------- |
| `pepper`        | `APP_PASSWORD_PEPPER`      | Required    |
| `memoryCost`    | `ARGON2_MEMORY_COST`       | `65536` KiB |
| `timeCost`      | `ARGON2_TIME_COST`         | `3`         |
| `parallelism`   | `ARGON2_PARALLELISM`       | `1`         |
| `outputLen`     | `ARGON2_OUTPUT_LEN`        | `32`        |
| `maxInputBytes` | `PASSWORD_MAX_INPUT_BYTES` | `128`       |

Numbers must be positive integers. `parallelism` is capped at 255 by the native binding.

## Parameter guidance

Argon2id cost parameters are a tradeoff between resistance to guessing and memory use. Start with the defaults and measure on production hardware.

| Scenario                     | `memoryCost` | `timeCost` | `parallelism` | Notes                              |
| ---------------------------- | ------------ | ---------- | ------------- | ---------------------------------- |
| Default web app              | `65536`      | `3`        | `1`           | 64 MiB per hash. Start here.       |
| High-traffic API             | `47104`      | `1`        | `1`           | 46 MiB, one pass. Measure latency. |
| Memory-constrained container | `16384`      | `3`        | `1`           | Lower memory, more iterations.     |
| Desktop or CLI tool          | `131072`     | `3`        | `1`           | 128 MiB if memory allows.          |

Two rules matter more than the table:

1. Measure hash and verify latency on the hardware you deploy. A verify that takes seconds will hurt login and invite abuse.
2. Budget total memory, not per-hash memory. Each concurrent hash holds `memoryCost` of RAM. Twenty logins at 64 MiB can use 1.25 GiB.

Use the rate limiter on credential endpoints and queue bursts if your login traffic is spiky.

## Rehashing

`needsRehash(hash)` returns true when:

- The hash is not Argon2id.
- The version is not 19.
- `memoryCost` is lower than the current config.
- `timeCost` is lower than the current config.
- `parallelism` differs from the current config.
- `outputLen` differs from the current config.

If the other parameters match, a hash with higher memory or time cost than the current config does not need a rehash. It is already at least as strong.

Call `needsRehash` after a successful verify, then rehash with the plaintext password you already have. Do not rehash without the plaintext.

Changing the pepper makes every old hash fail verification. `needsRehash` cannot detect a pepper change because the pepper is not in the stored string. Pepper rotation needs a planned migration, not a silent swap.

## Errors

```ts
import {
  InvalidConfigError,
  InvalidPepperError,
  PasswordHashError,
  PasswordTooLongError
} from "@/blocks/password-hash/errors";
```

| Error                  | When it is thrown                                            |
| ---------------------- | ------------------------------------------------------------ |
| `InvalidPepperError`   | The pepper is missing, not base64, or shorter than 32 bytes. |
| `InvalidConfigError`   | A numeric parameter is out of range.                         |
| `PasswordTooLongError` | The password exceeds `maxInputBytes`.                        |
| `TypeError`            | The password is not a string.                                |
| `PasswordHashError`    | Base class for the block's errors.                           |

`verifyPassword` returns `false` for a malformed or non-Argon2id stored hash. It still throws `PasswordTooLongError` and `TypeError` for caller mistakes. Oversized input is a bad request, not a failed login.

```ts
try {
  const valid = await hasher.verifyPassword(password, storedHash);
} catch (error) {
  if (error instanceof PasswordTooLongError) {
    return res.status(400).json({ error: "Password is too long" });
  }

  throw error;
}
```

## API reference

### `PasswordHasher`

```ts
class PasswordHasher {
  constructor(overrides?: PasswordHashConfigOverrides);

  hashPassword(password: string): Promise<string>;
  verifyPassword(password: string, storedHash: string): Promise<boolean>;
  needsRehash(storedHash: string): boolean;

  readonly currentConfig: Readonly<PasswordHashConfig>;
}
```

`currentConfig` includes the pepper. Do not log it or expose it through an admin endpoint.

### `PasswordHashConfig`

```ts
interface PasswordHashConfig {
  pepper: string;
  memoryCost: number;
  timeCost: number;
  parallelism: number;
  outputLen: number;
  maxInputBytes: number;
}
```

### `loadConfig`

```ts
function loadConfig(overrides?: PasswordHashConfigOverrides): PasswordHashConfig;
```

Reads environment variables and applies overrides. `PasswordHasher` calls this in its constructor.

## Security notes

- Use a unique pepper per environment. Do not reuse production secrets in staging.
- Keep the pepper out of logs, error reports, and client bundles.
- Enforce a minimum password length in your application. The block has no minimum; it only enforces a maximum byte length.
- Normalize Unicode only if your product requires it. Changing normalization later changes the password.
- Do not compare password hashes in application code. Use `verifyPassword`.
- For unknown accounts, verify against a dummy hash with the same parameters to reduce timing differences.
- Argon2 is memory-hard by design. Set container memory limits above `memoryCost` times your expected concurrency.

## When not to use it

- You need a managed identity provider that already stores credentials.
- You need passwordless authentication, OAuth, or passkeys. Use a dedicated flow.
- You run on a runtime without Node native bindings. `@node-rs/argon2` requires a runtime that supports them.
