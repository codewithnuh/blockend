The error handler block converts thrown values into a client-safe response. It classifies the error, redacts sensitive fields, logs or reports the event, and returns a status code plus a stable JSON envelope.

The core is framework-agnostic. Create one boundary and pass it to the adapter for your framework.

## Quick start

```bash
pnpm dlx blockend-cli init
pnpm dlx blockend-cli add error-handler
```

```ts
import express from "express";
import { AppError, createErrorBoundary } from "@/blocks/error-handler";
import { createExpressErrorHandler } from "@/blocks/error-handler/adapters/express";

const app = express();
const boundary = createErrorBoundary();

app.get("/users/:id", async (req, res) => {
  const user = await db.user.findUnique({ where: { id: req.params.id } });

  if (!user) {
    throw new AppError({
      code: "USER_NOT_FOUND",
      message: "User not found",
      category: "NOT_FOUND"
    });
  }

  res.json(user);
});

app.use(createExpressErrorHandler(boundary));
```

`createExpressErrorHandler` returns Express error middleware. Register it after your routes. It needs the boundary argument.

## Usage

### Express

```ts
import express from "express";
import { AppError, createErrorBoundary } from "@/blocks/error-handler";
import { createExpressErrorHandler } from "@/blocks/error-handler/adapters/express";

const app = express();
const boundary = createErrorBoundary();

app.get("/invoices/:id", async (req, res) => {
  const invoice = await db.invoice.findUnique({ where: { id: req.params.id } });

  if (!invoice) {
    throw new AppError({
      code: "INVOICE_NOT_FOUND",
      message: "Invoice not found",
      category: "NOT_FOUND"
    });
  }

  res.json(invoice);
});

app.use(
  createExpressErrorHandler(boundary, {
    getContext: (req) => ({
      userId: req.user?.id
    })
  })
);
```

The examples assume your auth middleware declares `req.user` and `request.user` on the framework request types. If `headersSent` is already true, the adapter calls `next(error)` instead of writing a second response.

### Fastify

```ts
import Fastify from "fastify";
import { createErrorBoundary } from "@/blocks/error-handler";
import { registerFastifyErrorHandler } from "@/blocks/error-handler/adapters/fastify";

const app = Fastify();
const boundary = createErrorBoundary();

registerFastifyErrorHandler(app, boundary, {
  getContext: (request) => ({
    userId: request.user?.id
  })
});

app.get("/invoices/:id", async (request) => {
  return db.invoice.findUniqueOrThrow({ where: { id: request.params.id } });
});

await app.listen({ port: 3000 });
```

The adapter sets Fastify's error handler and returns the serialized result.

### Hono

```ts
import { Hono } from "hono";
import { AppError, createErrorBoundary } from "@/blocks/error-handler";
import { registerHonoErrorHandler } from "@/blocks/error-handler/adapters/hono";

const app = new Hono();
const boundary = createErrorBoundary();

registerHonoErrorHandler(app, boundary);

app.get("/invoices/:id", async (c) => {
  const invoice = await db.invoice.findUnique({ where: { id: c.req.param("id") } });

  if (!invoice) {
    throw new AppError({
      code: "INVOICE_NOT_FOUND",
      message: "Invoice not found",
      category: "NOT_FOUND"
    });
  }

  return c.json(invoice);
});

export default app;
```

You can also use `createHonoErrorHandler(boundary)` and pass it to `app.onError()` yourself.

## AppError

Use `AppError` for errors you expect. The options object is required unless you are using the deprecated positional constructor.

```ts
throw new AppError({
  code: "PAYMENT_DECLINED",
  message: "The card was declined",
  statusCode: 402,
  category: "BAD_REQUEST",
  severity: "warning",
  isOperational: true,
  details: { reason: "insufficient_funds" }
});
```

| Option          | Type                                           | Default                                       |
| --------------- | ---------------------------------------------- | --------------------------------------------- |
| `code`          | `string`                                       | Required                                      |
| `message`       | `string`                                       | Required                                      |
| `statusCode`    | `number`                                       | Derived from `category`, otherwise 500        |
| `category`      | `ErrorCategory`                                | Inferred from `statusCode`                    |
| `severity`      | `"info" \| "warning" \| "error" \| "critical"` | `warning` for 4xx, `error` for 5xx            |
| `isOperational` | `boolean`                                      | `true` when `statusCode < 500`                |
| `cause`         | `unknown`                                      | None                                          |
| `metadata`      | `Record<string, unknown>`                      | None. Never sent to the client.               |
| `details`       | `unknown`                                      | None. Sent only when `isOperational` is true. |

Categories map to status codes when you do not set one:

| Category              | Status |
| --------------------- | ------ |
| `BAD_REQUEST`         | 400    |
| `VALIDATION`          | 400    |
| `AUTHENTICATION`      | 401    |
| `AUTHORIZATION`       | 403    |
| `NOT_FOUND`           | 404    |
| `CONFLICT`            | 409    |
| `RATE_LIMIT`          | 429    |
| `INTERNAL`            | 500    |
| `SERVICE_UNAVAILABLE` | 503    |

Only `AppError` instances and errors returned by your classifier can be operational. An arbitrary `Error` with a `statusCode` property is still treated as non-operational and returns 500.

## Boundary configuration

```ts
const boundary = createErrorBoundary({
  logger,
  reporter,
  classifier,
  serializer,
  sensitiveKeys: ["privateKey", "sessionId"]
});
```

| Option          | Description                                                         |
| --------------- | ------------------------------------------------------------------- |
| `logger`        | Object with `error(context, message)`. Logger failures are ignored. |
| `reporter`      | Object with `report(event)`. Reporter failures are ignored.         |
| `classifier`    | Maps an unknown error to `AppErrorOptions` or `null`.               |
| `serializer`    | Builds the response body. Defaults to `serializeErrorResponse`.     |
| `sensitiveKeys` | Extra key fragments to redact. Matching is case-insensitive.        |

### Classifier

Use a classifier for validation libraries and third-party errors:

```ts
import { z, ZodError } from "zod";

const boundary = createErrorBoundary({
  classifier(error) {
    if (!(error instanceof ZodError)) return null;

    return {
      code: "VALIDATION_FAILED",
      message: "Validation failed",
      statusCode: 400,
      category: "VALIDATION",
      details: z.treeifyError(error)
    };
  }
});
```

If the classifier throws, the boundary falls back to the default classification.

### Logging and reporting

```ts
const boundary = createErrorBoundary({
  logger: {
    error(event, message) {
      logger.error(event, message);
    }
  },
  reporter: {
    async report(event) {
      await errorQueue.publish(event);
    }
  }
});
```

The event contains the sanitized error and context. The logger is called with the event object first, then the message `"Application error"`.

### Sensitive data

The default redaction list covers:

- `password`
- `passphrase`
- `token`
- `authorization`
- `secret`
- `apikey`
- `cookie`

Matching is case-insensitive and ignores punctuation. Add your own fragments with `sensitiveKeys`. The sanitizer replaces circular references and functions, stringifies bigints and symbols, and truncates data beyond eight levels.

Redaction happens before logging, reporting, and serialization. `metadata` is for server-side diagnostics and is never included in the default client response.

## Adapters

### Express

```ts
createExpressErrorHandler(boundary, {
  getContext?: (request) => ErrorContextInput
});
```

Default context: `method`, `path`, and `requestId` from `request.id` or `x-request-id`.

### Fastify

```ts
registerFastifyErrorHandler(app, boundary, {
  getContext?: (request) => ErrorContextInput
});
```

Default context: `method`, path without the query string, and `request.id`.

### Hono

```ts
createHonoErrorHandler(boundary, {
  getContext?: (context) => ErrorContextInput
});

registerHonoErrorHandler(app, boundary, options?);
```

Default context: `method`, `path`, and `requestId` from the `requestId` variable or `x-request-id`.

## Response shape

The default serializer returns:

```json
{
  "success": false,
  "data": null,
  "error": {
    "message": "User not found",
    "details": {}
  },
  "requestId": "req_123"
}
```

`details` and `requestId` are omitted when they are not present. Non-operational errors always return status 500 and the message `"Internal server error"`, even if the original error message was more specific.

## Compatibility layer

The `express/` folder exists for code written against older versions:

```ts
import {
  asyncHandler,
  ERRORS,
  globalErrorHandler,
  HTTP_STATUS,
  throwError
} from "@/blocks/error-handler/express";
```

`globalErrorHandler` is a prebuilt Express middleware with a boundary, a console logger, and a Zod classifier. It is deprecated. New code should create a boundary and pass it to `createExpressErrorHandler`.

## When not to use it

- You already have a framework-wide error pipeline with the same envelope and redaction rules.
- You need error tracking only. Use a dedicated error tracker and keep your existing responses.
- You need to expose stack traces to clients. This block intentionally hides them.
