The package is `blockend-cli`; the executable is `blockend`. You do not need a global install:

```bash
pnpm dlx blockend-cli <command>
```

The npm equivalent is `npx blockend-cli <command>`. After installation, the `blockend` binary also works.

## `init`

Create `blockend.json` in the project root.

```bash
pnpm dlx blockend-cli init [options]
```

| Option   | Alias | Default | Description                                                |
| -------- | ----- | ------- | ---------------------------------------------------------- |
| `--yes`  | `-y`  | `false` | Accept detected defaults and overwrite an existing config. |
| `--json` |       | `false` | Write a JSON result instead of terminal output.            |

The command detects the framework, language, package manager, Redis, and `tsconfig.json` or `jsconfig.json` path aliases. It prompts for:

1. Whether to keep, overwrite, or regenerate an existing config
2. Blocks directory, defaulting to `src/blocks` or `blocks`
3. Framework, when detection fails
4. Redis variants, when Redis is detected

Generated config:

```json
{
  "$schema": "https://blockend.noorulhassan.com/schema.json",
  "environment": "express",
  "language": "typescript",
  "packageManager": "pnpm",
  "importRewriteStrategy": "remove",
  "includeRedis": false,
  "aliases": {
    "blocks": "@/blocks"
  },
  "paths": {
    "blocks": "./src/blocks"
  }
}
```

`installed` is added by `add`, not by `init`. With `--yes`, an existing `blockend.json` is overwritten without a prompt.

## `add`

Write a block into the project.

```bash
pnpm dlx blockend-cli add [block] [options]
```

| Option    | Alias | Default | Description                                                          |
| --------- | ----- | ------- | -------------------------------------------------------------------- |
| `[block]` |       |         | Registry key, such as `rate-limiter` or `logger`.                    |
| `--yes`   | `-y`  | `false` | Skip prompts, install missing dependencies, and overwrite conflicts. |
| `--json`  |       | `false` | Write a JSON result.                                                 |
| `--multi` | `-m`  | `false` | Select multiple blocks in one session.                               |

Without a block name, the CLI shows a selector. With `--multi`, it shows a multiselect. Space toggles a block and Enter confirms.

Behavior:

- Requires a TypeScript project. JavaScript projects are rejected.
- Filters blocks by the configured framework.
- Asks for a storage variant when more than one exists.
- In interactive mode, selects Redis automatically when `includeRedis` is true and a Redis variant exists. With `--yes`, it selects memory when available, otherwise the first variant.
- Checks `package.json` for missing or conflicting dependencies. Installation uses `pnpm add` for pnpm projects and `npm install` for every other detected package manager.
- Rewrites imports for `aliases.blocks` and `importRewriteStrategy`.
- Records installed files in the `installed` array.

`--yes` does not supply a block name. `add --yes` without a block is an error.

## `list`

List blocks available for the configured framework.

```bash
pnpm dlx blockend-cli list [options]
```

| Option   | Default | Description                                       |
| -------- | ------- | ------------------------------------------------- |
| `--json` | `false` | Write `{ success, environment, blocks }` as JSON. |

`list` requires `blockend.json` and network access to GitHub.

## `detect`

Report detected project settings.

```bash
pnpm dlx blockend-cli detect [options]
```

| Option   | Default | Description                              |
| -------- | ------- | ---------------------------------------- |
| `--json` | `false` | Write the full detection result as JSON. |

| Field                   | Meaning                                                                                |
| ----------------------- | -------------------------------------------------------------------------------------- |
| `framework`             | Detected backend framework, or `none`.                                                 |
| `language`              | `typescript` or `javascript`.                                                          |
| `packageManager`        | `npm`, `pnpm`, `yarn`, or `bun`.                                                       |
| `srcDir`                | Detected source directory path, such as the project's `src/`, `app/`, `lib/`, or root. |
| `importRewriteStrategy` | `rewrite` (append `.js`) or `remove` (extensionless).                                  |
| `hasRedis`              | Redis client found in dependencies.                                                    |
| `hasPrisma`             | Prisma found.                                                                          |
| `hasDrizzle`            | Drizzle found.                                                                         |

`detect` does not require `blockend.json`.

## `diff`

Preview files a block would write, without changing the project.

```bash
pnpm dlx blockend-cli diff <block> [options]
```

| Option    | Default  | Description                 |
| --------- | -------- | --------------------------- |
| `[block]` | Required | Registry key to preview.    |
| `--json`  | `false`  | Write diff results as JSON. |

The output marks each file as new, modified, or unchanged. Modified files include a line diff.

## `doctor`

Check the project and `blockend.json` for problems.

```bash
pnpm dlx blockend-cli doctor [options]
```

| Option   | Default | Description                  |
| -------- | ------- | ---------------------------- |
| `--json` | `false` | Write check results as JSON. |

Checks include:

- `package.json` and `blockend.json`
- `tsconfig.json` presence
- Lockfile for npm, pnpm, yarn, or bun
- Framework detection
- Redis, Prisma, and Drizzle detection
- `environment` and `paths.blocks` fields
- Whether the blocks directory exists

In text mode, `doctor` exits with code 1 when it finds errors. In JSON mode it returns `success: false` with `warnings` and `errors` arrays.

## `update`

Compare installed blocks with registry versions.

```bash
pnpm dlx blockend-cli update [options]
```

| Option    | Default | Description                              |
| --------- | ------- | ---------------------------------------- |
| `--json`  | `false` | Write update status as JSON.             |
| `--diff`  | `true`  | Show line diffs for blocks with updates. |
| `--apply` | `false` | Select blocks and apply updates.         |

Updates use the `installed` entries in `blockend.json`: block name, version, install time, files, and content hash. `--apply` asks which blocks to update, confirms before overwriting, downloads the new files, rewrites imports, and updates the installed metadata. In JSON mode it applies every available update without prompting.

## `mcp`

Start the MCP server or write a client config.

```bash
pnpm dlx blockend-cli mcp
pnpm dlx blockend-cli mcp init [options]
```

| Option      | Default | Description                                             |
| ----------- | ------- | ------------------------------------------------------- |
| `--client`  | Prompt  | `claude`, `codex`, `cursor`, `vscode`, or `windsurf`.   |
| `--dry-run` | `false` | Print the config without writing.                       |
| `--force`   | `false` | Skip the overwrite confirmation for an existing config. |
| `--yes`     | `false` | Skip prompts and default to Claude Code.                |

The MCP server exposes `list_blocks`, `detect_project`, `add_block`, `add_blocks`, `diff_block`, `doctor`, `update_check`, and `update_apply`. See [MCP server](/docs/01-getting-started/03-mcp).

## Requirements

- Node.js 20 or newer
- TypeScript project for `add`
- A supported framework: Express, Fastify, Next.js App Router, or Hono
- Network access to GitHub for registry commands
- A package manager: npm, pnpm, yarn, or bun is detected

Framework-specific blocks appear only for matching frameworks. Universal blocks such as `env-config` and `password-hash` work with every framework.
