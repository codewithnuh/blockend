---
title: MCP server
description: Connect an AI coding client to Blockend and let it inspect, preview, and install blocks.
---

Blockend includes a Model Context Protocol server. It exposes CLI operations as tools over the stdio transport, so a supported AI client can list blocks, inspect a project, preview files, and install blocks without you typing each command.

The tools run the Blockend CLI in your project. They can write files and install packages, so review the proposed changes.

## Quick start

Generate a project-local MCP config:

```bash
pnpm dlx blockend-cli mcp init --client cursor
```

Replace `cursor` with `claude`, `codex`, `vscode`, or `windsurf`. Restart the client, open the project, and ask it to list blocks or inspect the project.

Preview the config without writing files:

```bash
pnpm dlx blockend-cli mcp init --client cursor --dry-run
```

## Supported clients

| Client      | Config file             | Format                     |
| ----------- | ----------------------- | -------------------------- |
| Claude Code | `.mcp.json`             | JSON                       |
| Cursor      | `.cursor/mcp.json`      | JSON                       |
| VS Code     | `.vscode/settings.json` | JSON with `mcp.mcpServers` |
| Codex CLI   | `.codex/config.toml`    | TOML                       |
| Windsurf    | `.windsurf/mcp.json`    | JSON                       |

The generated server command is:

```bash
npx -y blockend-cli mcp
```

Example JSON for Claude, Cursor, or Windsurf:

```json
{
  "mcpServers": {
    "blockend": {
      "command": "npx",
      "args": ["-y", "blockend-cli", "mcp"]
    }
  }
}
```

VS Code uses the same server under `mcp.mcpServers`:

```json
{
  "mcp.mcpServers": {
    "blockend": {
      "command": "npx",
      "args": ["-y", "blockend-cli", "mcp"]
    }
  }
}
```

Codex uses TOML:

```toml
[mcp_servers.blockend]
command = "npx"
args = ["-y", "blockend-cli", "mcp"]
```

## Commands

### `mcp init`

```bash
pnpm dlx blockend-cli mcp init
```

Without `--client`, the CLI asks which client to configure. It merges the Blockend server into an existing JSON config. For Codex, it writes the TOML file directly.

| Option      | Default | Description                                             |
| ----------- | ------- | ------------------------------------------------------- |
| `--client`  | Prompt  | `claude`, `codex`, `cursor`, `vscode`, or `windsurf`.   |
| `--dry-run` | `false` | Print the target path and config without writing.       |
| `--force`   | `false` | Skip the overwrite confirmation for an existing config. |
| `--yes`     | `false` | Skip prompts and default to Claude Code.                |

Both `--force` and `--yes` skip the overwrite confirmation. JSON configs are merged, not replaced.

### `mcp`

```bash
pnpm dlx blockend-cli mcp
```

Starts the stdio server. Your AI client normally runs this command for you.

## Tools

| Tool             | What it does                                                                           |
| ---------------- | -------------------------------------------------------------------------------------- |
| `list_blocks`    | Lists block names, descriptions, and variants.                                         |
| `detect_project` | Returns framework, language, package manager, and project structure.                   |
| `add_block`      | Installs one block into a project. Requires `blockName` and an absolute `projectPath`. |
| `add_blocks`     | Installs several blocks. Requires `blockNames` and an absolute `projectPath`.          |
| `diff_block`     | Previews new, modified, and unchanged files without writing.                           |
| `doctor`         | Checks `blockend.json`, framework detection, and project layout.                       |
| `update_check`   | Compares installed blocks with registry versions.                                      |
| `update_apply`   | Applies available updates and rewrites imports.                                        |

`add_block` runs the equivalent of:

```bash
blockend add <block> --yes --json
```

That means it installs missing dependencies and overwrites conflicting files without asking. Use `diff_block` first. `projectPath` must be an absolute path to the project root. `add_blocks` runs the same command once per name, in order, and returns one result per block.

Example prompts:

- "List the blocks available for this project."
- "Preview the logger block."
- "Add the rate-limiter block with its memory store."
- "Check whether installed blocks have updates."

Use registry keys in tool arguments: `rate-limiter`, `logger`, `error-handler`, and so on. `rate-limit` and `pino-logger` are not valid keys.

## Safety

- Block tools write into your repository. Review the diff before accepting an install.
- `add_block` and `add_blocks` use `--yes`, so they can overwrite existing block files.
- Dependency installation can change `package.json` and your lockfile.
- MCP does not add authentication or sandboxing. Run the client in a project where file writes are acceptable.
- Keep `blockend.json` under version control so configuration changes are visible.

## Troubleshooting

If the client cannot start the server, run the generated command directly:

```bash
npx -y blockend-cli mcp
```

If it exits immediately, check Node.js 20 or newer and network access to npm and GitHub. Tools that accept `projectPath` need an absolute path. `list_blocks` uses the directory where the MCP server started, so launch the server from the project root.

Use `--dry-run` to confirm which file the CLI would write. Use `--force` only after backing up an existing MCP config.
