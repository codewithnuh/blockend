title: Initialize Blockend

---

The `init` command checks your project and creates `blockend.json`. Blockend uses this file to choose compatible blocks and place their files in the right folder.

Run the following command from the root of your project:

```bash
pnpm dlx blockend-cli init
```

The setup asks a few questions. You usually run it once per project.

## Quick start

Run the command from your project root and answer the prompts. Then add a block:

```bash
pnpm dlx blockend-cli init
pnpm dlx blockend-cli add rate-limiter
```

The CLI creates `blockend.json` and adds the block files to the folder shown in that config. Read [Add blocks](/docs/01-getting-started/02-adding-new-block) for variant choices, dependency prompts, and file conflicts.

---

## What `init` Does

During initialization, Blockend automatically:

- Detects your backend framework
- Detects whether your project uses TypeScript or JavaScript
- Discovers your import aliases from `tsconfig.json` or `jsconfig.json`
- Detects Redis support
- Configures where generated blocks will be placed
- Creates a `blockend.json` configuration file

These settings help the CLI generate files that fit your project.

---

## Interactive Setup

### Framework Detection

Blockend scans your project and attempts to detect the framework automatically.

Supported frameworks include:

- Express.js
- Fastify
- Next.js (App Router)
- Hono

If the detected framework is correct, press **Enter**. Otherwise, choose the framework your app uses.

---

### Blocks Import Alias

Next, Blockend asks where generated blocks should be imported from.

Example:

```text
@/blocks
```

or

```text
~/blocks
```

The alias is resolved automatically to the correct physical directory using your project's path mappings.

---

### Redis Support

If Redis is detected, Blockend will ask whether Redis-enabled block variants should be generated.

```text
Redis detected.
Enable Redis-backed block variants automatically?
```

Choose **Yes** to enable Redis variants for blocks that offer them. This does not create or configure a Redis server.

---

## Generated Configuration

After setup, Blockend creates a `blockend.json` file in your project's root.

Example:

```json
{
  "$schema": "https://blockend.noorulhassan.com/schema.json",
  "environment": "express",
  "language": "typescript",
  "includeRedis": true,
  "aliases": {
    "blocks": "@/blocks"
  },
  "paths": {
    "blocks": "./src/blocks"
  }
}
```

---

## Configuration Fields

### `$schema`

Specifies the JSON schema used by editors for validation and autocomplete.

### `environment`

The backend framework Blockend should target.

Supported values:

- `express`
- `fastify`
- `next`
- `hono`

### `language`

The language used by your project.

Supported values:

- `typescript`
- `javascript`

### `includeRedis`

Controls whether Redis-enabled block templates should be generated.

### `aliases.blocks`

The import alias used when generating blocks.

Example:

```text
@/blocks
```

### `paths.blocks`

The filesystem location where Blockend will generate new blocks.

Example:

```text
./src/blocks
```

---

## Existing Configuration

If a `blockend.json` file already exists, Blockend will ask how you want to proceed.

Available options:

| Option                | Description                                               |
| --------------------- | --------------------------------------------------------- |
| Keep existing config  | Cancel initialization and keep the current configuration. |
| Overwrite config      | Replace the existing configuration file.                  |
| Delete and regenerate | Remove the current configuration and generate a new one.  |

## Next Steps

After setup, add a block by its key. For example:

```bash
pnpm dlx blockend-cli add <block>
```

For example:

```bash
pnpm dlx blockend-cli add rate-limiter
```

```bash
pnpm dlx blockend-cli add health-check
```

```bash
pnpm dlx blockend-cli add env-config
```
